# Конвенции: статусы документов и подписание

> **Статус: принята (2026-09-10).** Политика подписи утверждена: для Кадров,
> Доверенностей и Корреспонденции бумага + скан подписанного оригинала —
> достаточно; реальная ЭП не вводится. Кандидат на ЭП в перспективе — только
> электронные исходящие письма (по email/ЭДО с юридической силой), если такой
> канал появится; до тех пор действует бумага + скан.

Документ фиксирует принятые соглашения по двум сквозным вопросам, чтобы новые
контуры делались единообразно, а имеющиеся расхождения были осознанными, а не
случайными. ВНД в этот документ не входит — у него собственная модель согласования
(фазы Primary/Repeat/FinalHold, матрица разногласий) и отдельный жизненный цикл
`VndStatus`, менять которые не планируется.

## 1. Статусы документов

В системе три способа хранения статуса — это осознанное разделение по природе
документа, а не разнобой:

| Способ | Где | Контуры |
|--------|-----|---------|
| Строковый `Document.StatusCode` (константы) | на единой карточке Document | **СЗ** (`SzStatus`), **Закупки** (`ProcurementStatus`) |
| `int`-enum на своей таблице | вне карточки Document | **Кадры** (`HrOrderStatus`), **Доверенности** (`PowerOfAttorney.Status`), **Корреспонденция** (`LetterStatus`), **Обязательства** (`ObligationPeriodStatus`) |
| `RouteInstanceStatus` (`int`-enum) | движок маршрутов | ортогонален статусу документа — это состояние *маршрута*, а не документа |

### Конвенция

1. **Новый тип документа, живущий на карточке Document, — строковый `StatusCode`.**
   Строка расширяется без миграции enum и читается в БД без словаря значений.
2. **Контур вне карточки Document ведёт свой `int`-enum статуса.** Это допустимо и
   не подлежит принудительному сведению: заведение таких контуров на карточку Document
   — отдельный крупный проект (см. ниже «Почему не сводим силой»).
3. **`RouteInstanceStatus` — состояние маршрута, а не документа.** Его нельзя мешать
   со статусом документа; документ узнаёт итог маршрута через обработчик завершения
   (`IRouteCompletionHandler`), а не читая `RouteInstanceStatus` напрямую.
4. **Мёртвых значений в enum быть не должно.** Если значение объявлено, но не
   выставляется ни одним переходом — либо реализовать переход, либо убрать значение
   (пример устранённого разрыва: недостижимый `LetterStatus.Sent` — добавлена операция
   отправки исходящего письма).

### Почему не сводим силой

Свести хранилище статусов к одному стилю — это миграция каждой документной таблицы,
переписывание каждого запроса и каждого экрана. Риск несоразмерен выгоде
«единообразия»: значения статусов регуляторны, ошибка на живых данных стоит дорого.
Разделение «на карточке — строкой, вне карточки — enum» отражает реальную разницу
контуров и признаётся нормой.

## 2. Подписание

Реальную электронную подпись (`ISignatureService`, шаг `StepKind.Signing` маршрута)
получают только контуры, идущие через движок маршрутов:

| Механизм | Контуры | Как «подписывается» |
|----------|---------|----------------------|
| **Реальная ЭП** через RouteEngine (Signing-шаг) | **СЗ**, **Закупки** | подпись на этапе маршрута + `ISignatureService` |
| **Подпись сменой статуса + бумажный оригинал/скан** | **Кадры** (`Sign` → `Signed`), **Доверенности** (`Issue` → `Active`), **Корреспонденция** (`Send` → `Sent`) | документ подписывается на бумаге и подшивается; в системе фиксируется статус и прикладывается скан |

### Конвенция

1. **Документ, проходящий согласование через RouteEngine, подписывается ЭП** на
   Signing-шаге маршрута. Это канонический путь для машинно-подписываемых документов.
2. **Документ, который по своей природе подписывают на бумаге** (кадровый приказ,
   доверенность, исходящее письмо), фиксирует факт подписания сменой статуса и
   **обязательно хранит скан** подписанного оригинала. Реальная ЭП для таких контуров
   сейчас не требуется — это осознанный выбор, а не пробел.
3. **Решение о введении ЭП для бумажно-подписываемых контуров — регуляторное.** Если
   регламент банка потребует ЭП (например, для исходящих писем), контур подключается к
   `ISignatureService` тем же способом, что СЗ/Закупки; до тех пор действует п. 2.

### Что проверить перед тем, как считать бумажный путь достаточным

- Скан подписанного оригинала обязателен и не теряется (у кадровых приказов и
  доверенностей — есть; см. `SzPaperService`/`HrOrder`/`PoaFile`).
- Статус «подписано/отправлено/выдано» достижим и необратимо фиксирует момент.
