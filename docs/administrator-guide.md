# Руководство администратора СЭД «Делосфера»

Документ описывает установку, настройку и сопровождение системы. Он не пересказывает
интерфейс — только то, что делает администратор и чего нет на экранах.

---

## 1. Состав системы

| Компонент | Назначение | По умолчанию |
|---|---|---|
| API (.NET 10) | Вся логика, маршруты, подписи | порт 5300 |
| Веб-клиент (React) | Интерфейс пользователей | порт 5174 |
| PostgreSQL | Карточки, маршруты, справочники, аудит | порт 5432 |
| MinIO | Файлы вложений | порты 9000–9001 |
| Служба каталогов AD/LDAP | Учётные записи и вход | порт 389/636 |
| SMTP-relay банка | Исходящие уведомления | порт 25/587 |

База и файловое хранилище связаны: карточка без файла и файл без карточки не
восстанавливают документ. Копируются и восстанавливаются они всегда вместе.

---

## 2. Обязательные секреты

Система не стартует, пока не заданы два значения. Это сделано намеренно: пустой ключ
подписи токенов означает, что любой может подделать вход.

| Ключ | Что это | Требование |
|---|---|---|
| `Jwt:Key` | Ключ подписи токенов | не короче 32 символов |
| `ConnectionStrings:DefaultConnection` | Подключение к базе | — |

Задаются переменными окружения или `dotnet user-secrets`. В файлы конфигурации в
репозитории секреты не кладут.

Первый администратор создаётся из `Bootstrap:AdminEmail` и `Bootstrap:AdminPassword`.
После первого входа пароль меняется, а значения из конфигурации убираются.

## 3. Настройка интеграций

### Служба каталогов (INT-01)

Секция `Ldap`. Имена атрибутов вынесены в настройки, потому что в Active Directory
логин лежит в `sAMAccountName`, а в OpenLDAP — в `uid`.

```
Ldap:Enabled                 true
Ldap:Host                    dc.keremetbank.kg
Ldap:Port                    636
Ldap:UseSsl                  true
Ldap:BaseDn                  dc=keremetbank,dc=kg
Ldap:BindDn                  cn=sed-reader,ou=service,dc=keremetbank,dc=kg
Ldap:BindPassword            (только через секреты)
Ldap:LoginAttribute          sAMAccountName
Ldap:DisabledAttribute       userAccountControl
Ldap:CreateMissingUsers      true
Ldap:CreateMissingOrgUnits   false
```

Порядок первого запуска:

1. `GET /api/integrations/directory/status` — интеграция включена?
2. `GET /api/integrations/directory/preview` — что система видит в каталоге. Записи
   без адреса почты синхронизировать нельзя: почта — идентификатор учётной записи.
3. `POST /api/integrations/directory/sync` — синхронизация.

Синхронизация **не выдаёт прав**. Роли назначает администратор: имена групп в домене
и ролей в СЭД совпадают редко, а автоматический перенос раздал бы лишний доступ.

Ушедшие из каталога деактивируются, но не удаляются — за сотрудником остаются подписи
и резолюции.

### Корпоративная почта (INT-02)

Секция `Mail`. Письма ставятся в очередь `outgoing_email` и уходят фоновой отправкой
раз в полминуты. Если relay недоступен, письмо остаётся в очереди с числом попыток;
исчерпав их, помечается неудачей, но не удаляется — недоставленное уведомление должно
оставлять след.

Проверка: `select * from outgoing_email where sent_at is null and not failed;`

### Электронная подпись (SIG-02, INT-03)

Закрытый ключ остаётся на рабочем месте подписанта. Система отдаёт хеш версии файла,
криптопровайдер подписывает его, обратно приходят подпись и сертификат.

Серверная проверка ограничена RSA и ECDSA. Сертификаты ГОСТ Р 34.10 (УЦ «Инфоком»,
ТУМАР-CSP) отклоняются: принять подпись, которую система не в состоянии проверить,
хуже, чем отказать. Для их поддержки подключается адаптер СКЗИ — отдельная работа.

Цепочка доверия до корневого УЦ не строится: список доверенных центров банка не
согласован. Проверяются соответствие подписи хешу и срок действия сертификата.

## 4. Права и роли

Права фиксированы в коде (`PermissionCode`), роли собираются из них администратором
в разделе «Роли и права».

Ключевые права:

| Право | Что открывает |
|---|---|
| `ManageUsers`, `ManageRoles` | Учётные записи и роли |
| `ManageGeneralDictionaries` | Справочники, типы документов, общие представления журналов |
| `ViewMeetings` | Раздел «Заседания» |
| `ManageKpaMeetings` и аналоги | Ведение заседаний своего органа |
| `MemberOfKpa` и аналоги | Полная повестка своего органа |
| `ExportFullStatisticsReport` | Выгрузка аналитики |

Разделение членства и ведения не формальность: секретарь ведёт заседания, член органа
видит повестку целиком, остальные — только вопросы, где они названы.

## 5. Настройка без программирования

- **Справочники** (GEN-07): `/api/admin/dictionaries`. Код справочника после создания
  не меняется — на него ссылаются поля типов документов.
- **Типы документов** (GEN-06): `/api/admin/document-types`. Тип описывается полями и
  шаблоном маршрута. Вид поля и привязанный справочник после создания не меняются: в
  карточках уже лежат значения прежнего вида.
- **Представления журналов** (GEN-10): `/api/admin/views`. Общие заводит администратор,
  личные — каждый себе.
- **Пороги плана актуализации** (PLN-03/04): `/api/actualization/plan/settings`.

Тип или справочник, на который уже ссылаются данные, не удаляется — выключается.

## 6. Фоновые процессы

| Процесс | Расписание | Что делает |
|---|---|---|
| `OverdueWorker` | раз в минуту | Автоакцепт и эскалация по просроченным этапам |
| `MailWorker` | раз в 30 секунд | Отправка очереди писем |
| `SzDeadlineWorker` | 9:00 по времени банка | Напоминания по срокам поручений СЗ |
| `MeetingReminderWorker` | 9:00 | Напоминания по протоколам заседаний |
| `PlanReminderWorker` | 9:00 | План актуализации: сводка 1-го числа, критические сроки |

Все расчёты календарных дат идут по времени банка (Asia/Bishkek), а метки времени
хранятся в UTC. Путать их нельзя: письмо «срок завтра», отправленное по UTC, придёт
ночью.

## 7. Резервное копирование (NFR-02)

Скрипты: `ops/backup.sh` и `ops/restore.sh`.

```
30 1 * * * /opt/delosfera/ops/backup.sh >> /var/log/delosfera-backup.log 2>&1
```

Копия включает выгрузку базы (формат custom) и зеркало файлов MinIO, рядом кладутся
контрольные суммы. Хранение по умолчанию 30 дней, меняется `RETENTION_DAYS`.

Восстановление запускается только вручную и требует ввести имя базы для подтверждения.
Перед восстановлением проверяются контрольные суммы и останавливается сервис.

**Проверка восстановления — часть регламента, а не формальность.** Раз в квартал копия
разворачивается на тестовом контуре, и проверяются три вещи: вход в систему, открытие
документа с вложением, выгрузка отчёта. Копия, из которой ни разу не восстанавливались,
не считается копией.

## 8. Информационная безопасность (NFR-03)

- **Парольная политика** — секция `Security:PasswordPolicy`: длина, состав символов,
  число неудачных попыток и время блокировки. Меняется без пересборки.
- **Блокировка после подбора**: учётная запись запирается на заданное время. Ограничение
  по адресу тоже стоит, но оно не спасает от подбора с разных адресов по одной учётке.
- **TLS**: `UseHttpsRedirection` и HSTS вне среды разработки. Сертификат ставится на
  обратном прокси банка.
- **Заголовки безопасности** ставятся приложением, а не прокси: конфигурация прокси
  живёт отдельной жизнью, а заголовки должны ехать вместе с приложением.
- **Журнал администраторов**: заведение и изменение учётных записей, блокировка, смена
  состава ролей и прав — в таблице `audit_entry`. Журнал не редактируется из интерфейса.

Разбор «откуда у сотрудника доступ»:

```sql
select at, action, payload_json
from audit_entry
where entity_type in ('User', 'Role')
order by at desc;
```

## 9. Обновление версии

1. Снять резервную копию (`ops/backup.sh`) — до всего остального.
2. Остановить сервис.
3. Выложить новую версию.
4. Запустить: миграции применяются на старте.
5. Проверить вход, открытие документа с вложением, выгрузку отчёта.

Флаг `Database:RecreateOnStartup` в промышленном контуре не включается никогда: он
удаляет базу целиком. Он существует только для отладки.

## 10. Диагностика

| Симптом | Куда смотреть |
|---|---|
| Не приходят письма | `outgoing_email`: `last_error`, `attempts`, `failed` |
| Доменный вход не работает | `GET /api/integrations/directory/status`, затем `/preview` |
| Подпись отклоняется | Срок действия сертификата; алгоритм (ГОСТ не проверяется) |
| Документ «завис» на этапе | `route_participant.state`, `due_at`; открытые замечания блокируют автоакцепт намеренно |
| Не строится график в отчётности | Логи API: ошибки выборки по датам |

Полезные запросы:

```sql
-- Маршруты, стоящие дольше недели
select i.id, d.title, i.status, i.started_at
from route_instance i join document d on d.id = i.document_id
where i.status = 'Running' and i.started_at < now() - interval '7 days';

-- Просроченные поручения по служебным запискам
select a.id, a.due_date, u.full_name
from sz_assignment a join "user" u on u.id = a.assignee_user_id
where a.state = 0 and a.due_date < current_date;
```
